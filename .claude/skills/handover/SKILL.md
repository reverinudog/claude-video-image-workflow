# ハンドオーバー

要約だけで終わらせず、次のセッションが迷わず続きから入れる状態にして終える。Git で記録する（重いメディアは .gitignore で除外）。ブランチの運用は CLAUDE.md に従う。

## 手順

1. **取りこぼし確認**：`node review-tool/claude.mjs pending`。未完了の依頼があれば、対応するか、状態を案件READMEに書いてユーザーに伝える。各版の `.review.json` に未対応メモが残っていないかも見る。
2. **案件の状態を記録**：`<案件>/README.md` の冒頭「状態」欄を更新する。
   - 最終版（納品版）のファイル名と長さ、納品したかどうか、残っている作業
   - 次に同じ案件を触る人が最初に読むべきこと（なければ書かない）
3. **教訓の整理**（`docs/LESSONS.md` の目次 → 該当カテゴリへ追記）。書く前に次を全部満たすか確かめる：
   - 今回**実際に起きた**ことで、**原因と対処がわかっている**
   - 次回知らないと同じ時間を失う（コードや手順書を読めばわかることは書かない）
   - 1項目は数行。見出しで中身がわかる
   
   書かないもの：今回だけの事情、推測の「〜かもしれない」、ツールの一時的な不具合、「常に〜しない」のような根拠の薄い禁止。
   既存の教訓と食い違ったら、追記ではなく**古いほうを書き換えるか消す**。役に立たなくなった教訓も消す。
4. **手順書・入口の更新**：手順やツールの使い方が変わったら `docs/workflow.md` を直す。`CLAUDE.md` は入口なので、全案件に効く約束事だけ（80行以内を保つ）。
5. **ユーザーの好みの反映**：今回のフィードバックで全案件に効く好み（口調、演出、音量など）が増えたら `CLAUDE.md` の「依頼主の好み」へ。案件固有の指示は案件READMEへ。
5.5 **新しい表現を motion-kit に還元**：今回の案件で新しく作った表現・よくなった部品のうち、他の案件でも使えそうなものを `motion-kit/src/kit/` に入れ、見本に1件足して `node motion-kit/tools/catalog.mjs` で演出カタログを作り直す（手順は `motion-kit/CATALOG.md` の「増やし方」）。依頼主に「良かった」「いらない」と言われた演出は使いどころに書く。足すものがなければ飛ばす
6. **後片付け**（自分が作ったと確かめた使い捨てのものだけ）：
   - `video/out/check/` の確認用静止画
   - スクラッチパッドの一時ファイル
   - 書き出した旧版の動画は**消さずに**、容量（合計）をユーザーに伝えて判断を任せる
7. **外部メモリ**：Claude のメモリを使っているなら、「このフォルダの CLAUDE.md を読め」という入口だけに保つ。中身をメモリへ複製しない。
8. **Gitに記録**：
   - `git status --short` で変更を確認。メディア（mp4/wav/mp3/clips）が紛れていたら .gitignore を直す
   - `git add -A` → `git commit`（メッセージは日本語でよい。例：`製品紹介動画: v6納品、ハンドオーバー`）
   - リモート（`git remote -v`）が設定されていれば push。未設定なら何もしない（勝手に作らない）
9. **引き継ぎ要約をユーザーに出す**：
   - 完了したこと（納品版）
   - 記録・更新したファイル（教訓を足した／足さなかった理由）とコミット
   - 未確認のこと・残っていること
   - 次回の始め方（例：「次の案件フォルダを作って台本から」）
