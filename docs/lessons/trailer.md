# トレーラー・PV（曲が主役の動画）の教訓

2026-10-03 ゲーム紹介動画（横長 v8・ショート v1 で採用。文字のモーションが主役）、2026-09-25 ゲームのトレーラー（1作目）（v1〜v3、実験として終了）と、2026-09-26 シナリオのトレーラー（v15 で採用）、2026-09-29 書籍のトレーラー（横長 v13・ショート v3 で採用）で分かったこと。
シナリオのトレーラーは「グリルミー5問 → 構成メモ → 組む」で進めて、流れ（構成）への指摘はほぼ出なかった。直しは見た目と曲の切り方に集中した。

## 構成
- **最初に依頼主とグリルミーで流れを話し合う時間を取る**（依頼主の振り返り 2026-09-26）。v2 前のインタビューは「曲・色・演出」など見た目の質問が中心で、「何をどの順で伝えるか」の認識合わせが抜けていた
- **組む前に構成メモ（ざっくり1行ずつの流れ）で合意する**。v1・v2 は合意なしで作って「ゲームプレイ動画っぽい」「何がどうなのか分からない」になった。構成メモは情報量を少なく（秒数・素材・演出は書かない）。タイムライン風の詳細な画面は「見にくい・認知負荷が高い」でNGだった
- **見る人は前提知識ゼロ**。ストーリー（会話）場面の切り抜きは、前後の文脈がないと面白さが伝わらない。「書いたこと→起きたこと」の実例も、文脈なしでは分かりにくかった
- 図解（モーショングラフィックス）で仕組みを見せる案は方向としては合っていたが、v3 でも「結局わかりにくい」だった。仕組みの説明を積むより、一目で「おお」となる強い例を1つ見つけてから組むべき

## 曲の使い方
- **曲の「最後の一打」は、音量を測ってから使う**（ゲーム紹介動画）。ある曲の最後の和音は -17dB で静かに始まって1小節かけてふくらむ音で、盛り上がりの頂点から飛ぶと約19dB落ちて「急に終わってる感じ」と言われた。直し方：盛り上がりの着地（次の小節の頭の一打）を0.35秒鳴らして0.55秒で消し、その下に最後の和音をふくらみ始めた所から重ねて引き継ぐ＋最後の和音だけ +8dB した素材に差し替え。つなぎ目の前後を0.4秒刻みで `volumedetect` して落ち込みが無いことを確かめる
- **尺を縮めるときは、同じ形をくり返す4小節を1回ぶん飛ばす**（ゲーム紹介動画 v4）。小節ごとの和音の似かた（`librosa.feature.chroma_cqt` の平均のコサイン類似度）が0.95以上の小節の頭どうしなら自然につながった（波形の相関は0.17でも問題なし。相関ではなく和音で見る）
- 曲がいきなり始まると文字も唐突になる（「あまりに唐突にテロップ表示が始まりすぎ。ためがほしい」）。曲の前に曲なしの導入を8拍ぶん置き、暗い映像へゆっくり寄りながら上がっていく音と小さい文字 → 曲の頭の一打で叩きつけ、で通った
- **曲の切りどころを先に見つけてから構成を合わせる**（シナリオのトレーラーで v1〜v5 の4回やり直した末の結論。依頼主の提案）。小節ごと（180BPMなら1.33秒）に低音・高音・拍の強さを一覧にすると、「ため（低音が抜ける）→ 落ち」「曲の頭の一打」「曲の最後の一打」が数字で見える。拍の格子は、onset の強さの合計が最大になる BPM と位相で合わせる（`ゲームのトレーラー（1作目）/work/beats.py` も参照）
- **曲の途中から始める・途中で切って終わると「始まりと終わりが中途半端」**。曲の本当の頭と、本当の最後の一打を使うと締まる。最後の一打の余韻は約1秒でフェードして切り、その約1秒後に締めの演出（シナリオのトレーラーはテレビの電源オフ）
- **サビの途中で別の小節へ飛ぶと継ぎ目が聞こえる**。4小節周期の同じ位置でも中身（旋律など）が違う（波形の相関は0.3〜0.5しかなかった）。飛ぶのは「イントロ → ため」「サビの終わり → 次の区間の頭」のような区切りだけにし、飛び先の直前の小節と一番似ている小節のあとで飛ぶ。つなぎ目は0.1秒ほどクロスフェード
- **曲を途中で止めて、曲なしをはさんでまた戻すと「ぶつ切り」**（シナリオのトレーラー v3）。曲なし（環境音だけ）にするなら、曲が始まる前（開演前のざわめきなど）に置く
- 曲を短い間隔で何度も切り替えない（ゲーム v3 は数秒〜十数秒ごとに飛ばして「変わりすぎ」）。切り替えは2〜3回まで

## 音
- NPC（ゲームキャラ）の声の大きさは場面の役割で決める：声が主役の場面は下げない。添えるだけの場面なら -20dB くらいまで下げてよい（v3 は図解が主役だったので -20dB）。決める前に「この場面の主役は声か」を確かめる
- 声＋曲でピークが0dBを超えやすい → 仕上げにリミッター（workflow.md 参照）。区間ごとの音量も測る
- 迫る音（逆再生シンバル・ライザー）が鳴っている所に打撃音を重ねると「ちょっとノイズ」（書籍のトレーラー）。迫る音は「もう少し早く」と言われたので、長くして早めから聞こえるようにした（鳴りきるのは落ちの頭のまま）
- 合成した効果音を左右で少し（0.7ms）ずらして広げると、モノ（スマホのスピーカー）で鳴らしたときに櫛形のうなり（スペクトログラムに周期的な横縞）が出た（2026-10-04、motion-kit の合成SE を `audio/se_sheet.py` で見て気づいた）。広げたいなら左右を別のノイズから作る
- 効果音は、心音などの繰り返しを等間隔にする（間隔がばらつくと「急に速くなった」に聞こえた）。手持ちにない短いSE（シャッター・通知・打鍵・電源オフ・ライザーなど）は Python で合成して通った（`シナリオのトレーラー/README.md`）

## 見た目
- **文字のモーションが主役の動画で「安っぽい」と言われた原因と直し方**（ゲーム紹介動画 v1→v2）。原因：全部同じ「拡大して叩きつけ」・全部中央・全部同じ大きさ・黒い帯。直し方：入り方を3種に使い分け（下からせり上がる／字間が詰まりながらぼけから現れる／ここぞだけ残像つきの叩きつけ）、助詞や「も。」は半分の大きさ・キーワードは大きく金のグラデーション、黒い帯→文字の後ろだけやわらかく暗く、出ている間もゆっくり寄る、消えるときはぼけて字間が開く、和文は明朝＋英字は作品のロゴと同系統の書体
- **背景（ゲーム画面）のカメラは「さりげなく」**。寄り・パンを大きくしたら「激しすぎ。見てて疲れる」、量だけ抑えても2拍ごとの短いショットでは「ぐわんぐわん動く」と言われた（短いほど速く動く）。量と**速さ**の両方に上限を付ける：1ショットで寄り引き4%・横移動70pxまで、かつ1秒に1.2%・20pxまで、一定の速さ。切り替わりの瞬間の寄り（punch）もやめて明るさだけ。半拍ごとの切り替えもやめる（`ゲーム紹介動画の案件/video/src/parts.tsx` の Cam）
- 画面を並べる「ため」は、6枚より**画面いっぱいの枚数を斜めに倒した壁**（同じ映像は時間ずらし、手前から奥へ灯る、奥は暗く、全体はゆっくり引く）が通った。機能がいくつもあって「そんなに重要じゃない」ものは、1つずつ見せずに 2x2 に並べて一度に
- 「──」を文字で並べると字間が空いて「チープ」（過去にも何度か）。続く─はまとめて**1本の線（div）で描く**
- 2行のテロップを右寄せにすると、短い行の行頭がずれて見える。かたまりの置き場所（右上など）と、行どうしのそろえ方（左そろえ）は分けて指定する
- ここぞの叩きつけで集中線を2回使ったら、3回目は「別の派手演出で」と言われた → 火花が散る（金と白の線が飛び散って重力で落ちる）＋後ろから広がる金色の光。同じ演出のくり返しは避ける
- 同じ言葉の文言を画面とテロップで重ねない・次のテロップと意味が重なる文言は削る。テロップと映像の内容を合わせる（「行動」のテロップには行動を打つ画面）
- **画面が2秒以上止まると「表示の変わらない時間が気になる」**。読ませ終わったら、次へのため（ゆっくり寄る＋上がっていく音＋最後に白く飛ぶ）にする
- **一瞬大きく出す文字は、最終位置と中心をそろえるか、はっきり別の場所（画面の端で見切れる位置）に出す**。中心がずれた重ね方は「左右に謎に動く」と3版続けて指摘された
- 背景と同じ色の文字や、白い文字に走る白い光は見えない。光で見せられないときは、弾む・縁取りが広がるなど動きで見せる
- 16:9 の背景素材を無理にはめるより、単純な背景（無人のステージなど）はコードで描くほうがよかった。照明の向き・色・カメラの動きを後から自由に直せる
- 登場人物の立ち絵は頭が切れたままにしない。縦にゆっくり動かして、頭まで見える時間を十分に取る
- **テロップに飾りを足さない**（書籍のトレーラー）。短冊の外の白い罫線・開くときに縁を走る光・章立て風の小さな英字・文字が灯る光は、「謎の白い線いらない」「ルビみたいなのいらない」「点滅いらない」と3版続けて外すことになった。黒い帯と文字、ぼけから浮かぶ入り方で十分
- 日本語の題名がある画面に、同じ題名の英字を並べない（「浮いてる」「いらない」と横長・縦で2回）
- ここぞの一文を一度に出す演出の強さ：「ちょっとしたエフェクト」→「ちょびっとすぎてわからない」と2往復して、1.5倍の大きさから叩きつけ（少し行き過ぎて戻る）＋赤青の残像が左右から集まる＋一瞬の白み＋小さな揺れ、全部0.3秒で収まるくらいで採用になった

## 縦長（ショート）版
- ゲーム紹介動画 のショートは修正なし（v1）で採用。ゲーム画面（16:9 のUI）は、幅いっぱいの枠（y=400〜1420）に見せたい所だけ拡大して映し、文字は主に枠の上の空き、叩きつけは2段に割って枠の中央。部品は画面の大きさをコンテキスト（`FrameCtx`）で受け取る形にして共用し、縦用には寄る位置と文字の大きさ・場所だけ書いた別ファイル（`timeline_v.ts`）
シナリオのトレーラーのショート版は「横長版と流れ・曲を共有して配置だけ組み直す → 配置案を構成メモで合意 → 組む」で、メモ3件の修正1回（v2）で採用になった（2026-09-27）。書籍のトレーラーも同じ進め方で、修正2回（v3）で採用（2026-09-29）。
- 縦画面に横長と同じ周辺減光（`radial-gradient(ellipse …)` の既定の大きさ）を当てると、楕円が縦長になって左右と四隅が暗くなり「四隅の影が目立ちすぎ・縦に長いの違和感」と言われた。縦は横に長い楕円（例：`ellipse 130% 58%`）で薄くする
- ショートはスマホで見るので文字を一回り大きく（書籍のトレーラー：短冊 52→58、名前 110→150、紹介文 38→50、概要の値 36→42）。テロップと立ち絵は重なってよい（依頼主）
- 横長のスチルを縦に切ると絵の3割ほどしか入らない。1枚の中をカメラで横に流す（差し出した手 → 顔）と全体が見せられた
- 縦長で画像の左右の端をぼかして切ると「もや」に見えて不評だった。使いたい部分だけを幅いっぱいに拡大して、要らない部分は画面の外に出す（下端のぼかしは可）
- 縦長では立ち絵が全身入るので、上下に流すより顔へ向かって徐々に拡大（依頼主）
- 飾り（ハートなど）を顔に重ねると「額にある感じ」になる。髪や背景の上に置く
- 大きい文字を2行に割って語尾だけ残る（「〇〇／だ。」）なら、語尾は前の小さい行と同じ大きさで右寄せ（依頼主）
- 大事な文字は、ショートの説明文とボタンを避けて下から約350px・右端から約120pxに入れない

## 素材
- **撮り直す前に、過去の制作で撮った素材と撮影の仕組みを探す**（ゲーム紹介動画）。過去の実プレイ録画と、台本どおりに画面を動かす撮影スクリプト（AIを呼ばない）が残っていて、新しく撮らずに済んだ。素材は1秒刻みのコマ一覧（`ffmpeg -vf fps=1,scale=400:-1` → `magick montage`）で「何秒に何が映るか」を先に洗い出し、使う瞬間（打ち込み開始・クリティカルなど）は0.1秒刻みで確かめる
- 打ち込みなど一瞬で終わる動きは、0.5〜0.6倍速にすると見せ場になる
- 顔を映す：ゲーム画面の台詞帯やテロップで顔アイコンを隠さない。顔のアップはゲーム左下の顔アイコンを切り抜くと大きく使える
- 購入シナリオの素材は規約で二次配布禁止のことがある → `public/img/` を .gitignore に入れて Git（GitHub）に上げない
- 苗字など、本人は気にしない情報がネタバレになることがある。名前を出す前に、公開情報に載っている表記か確かめる
