## 今回の判断（この制作の解釈）
- **「安っぽさ」の正体は単調さ**（ゲーム紹介動画 の教訓）なので、部品の数より「同じに見えないこと」を優先した。入り方は動きの原理が違うものだけを足した（JIZURA の enter 100種のうち、数字違いのものは入れていない）
- **派手な部品ほど「使いどころ」を名前の横に書いた**（slam は「ここぞだけ」など）。依頼主の「動きは多すぎると気が散る」「さりげなく」を部品の既定値に入れた（カメラの上限・drift 3.5%・揺れは6割）
- **つなぎは基本 cut**。毎回の派手なつなぎは visual-design.md でも避けたい失敗に入っている。つなぎは「意味があるとき」の選択肢として名前で呼べるようにした
- **音は合成を厚くした**：効果音ラボは便利だが、ダウンロードのたびに承認が要り、規約上「効果音を流して紹介する動画」「テンプレートへの組み込み」ができない。合成なら kit の見本にも入れられ、長さを拍に合わせて作り直せる
- **フォーリー（物の音）・生楽器・声は合成しない**（合成だと安っぽい）。必要なときに効果音ラボの候補を挙げて承認を取る（sound-sources.md）

## 確かめたこと（2026-10-04）
- 見本の動画を書き出し、各部品の動きをコマ送りの一覧（`tools/sheet.mjs`）で確かめた。直したもの：
  - 霧が画面全体を白く覆っていた（色の重ね方の誤り）→ ノイズの明るさを濃さにして色は tint に
  - 立方体のつなぎで面の間にすき間ができ、入る面が早く見えた → 立方体の中心のまわりに回し、半分までは出る面を手前に
  - 後ろから消える untype が前から消えていた → 逆順に
  - 見本の背景にしたキービジュアルにロゴが入っていた → ゲーム画面の上の方だけを使う
- 合成SE は波形とスペクトログラムの一覧（`audio/se_sheet.py`）で確かめた。左右を 0.7ms ずらして広げる処理が、モノで聞くと櫛形のうなり（周期的な帯）を作っていた → やめた（スマホのスピーカーはモノのことが多い）。音程で上がるためは最後にクリックが出ていた → 15ms のフェード
- 曲の地図（`audio/song_map.py`）をある曲で試し、ゲーム紹介動画 で手で見つけた値（150BPM・最後の一打 145小節・20〜23小節と24〜27小節が同じ形）と一致した
- **耳では聞いていない**（この環境では再生できない）。効果音の質・音量の釣り合いは依頼主に SE の見本で聞いてもらう
